Registers hold per-thread live operands/results and are also an occupancy resource. Shared memory is explicitly managed on-chip CTA storage and is central to operand reuse. L1/TEX is the SM-side hardware-managed cache/request subsystem. L2 is GPU-wide. HBM is the large off-chip global-memory backing store.

Why GEMM?

For C=A×B, naïve execution repeatedly consumes A and B operands from the global hierarchy. Tiling allows a block to cooperatively stage subsets of A and B into shared memory and reuse them many times, increasing arithmetic intensity.

Naive:
HBM/L2 -> A,B -> Registers -> FMA -> C

Tiled:
HBM/L2 -> A/B tiles -> Shared Memory -> repeated reuse -> Registers -> FMA

Async tiled:
load Tile N+1 into alternate shared buffer
          ||
compute Tile N from current shared buffer

Hopper:
TMA -> Shared tiles -> operand pipeline -> Tensor Cores

Software pipeliningCan future data movement overlap current compute?

cp.async and software pipelining

Traditional conceptual staging is global → register → shared. Asynchronous-copy mechanisms allow software to initiate future global-to-shared movement and perform independent work before waiting for the destination data.

Naive:
LOAD tile0 -> WAIT -> COMPUTE tile0 -> LOAD tile1 -> WAIT -> COMPUTE tile1

Pipelined:
LOAD tile0
           COMPUTE tile0 =================
                LOAD tile1 --------------->
                                      COMPUTE tile1 =================

Double buffering alternates shared-memory buffers so one buffer is consumed while another is filled.

Hopper TMA

The Tensor Memory Accelerator is Hopper's specialized mechanism for asynchronous bulk movement of multidimensional tensor tiles. Conceptually, software describes a tensor/tile transfer and hardware assists with multidimensional address generation and movement into the shared-memory staging pipeline.

Starting experiment: naïve FP32 GEMM

We begin deliberately with one thread computing one C element:

C[row][col] = 0
for k = 0..K-1:
    C[row][col] += A[row][k] * B[k][col]

Before coding the H200-sized version, the first exercise will trace a 4×4 GEMM by hand: which A/B values each thread needs, what adjacent warp lanes access, where reuse exists, what traffic is redundant, and how a shared-memory tile changes that traffic.
